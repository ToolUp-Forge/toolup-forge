# 0.10.0 — portable connector contract (Phases 250–255)

**What changes.** The AI connector value types — `AIProviderMessage`, `AIProviderToolCall`,
`AIProviderToolResult`, `AIProviderToolDef`, `AIProviderResponse`, `TokenUsage`,
`AIProviderCapabilities`, `AIProviderError`, `AIContentPart` / `ImagePayload` — moved **assembly**:
they are now defined in `ToolUp.AI.Wire` (`Contract.fs`), still under the `ToolUp.Platform.AI`
namespace. `ToolUp.Platform.Core` 0.10.0 references `ToolUp.AI.Wire`, so every existing consumer
sees the same names transitively. `IAIProvider` / `IAIProviderDefaults` stay in
`ToolUp.Platform.Core` with unchanged signatures; the `#if !FABLE_COMPILER` guard around
`IAIProviderDefaults.sendStructuredViaFallback` is gone (structured-output post-validation now runs
through the portable `JsonValue`), so the entire connector contract compiles under Fable.

Additive alongside the relocation: the `IHttpTransport` seam (`HttpRequest` / `HttpResponse`,
`HttpRequest.post`, `HttpResponse.isSuccess`), `ErrorClassifier` (status → `AIProviderError`), and
`RetryRunner` (Phase 251); portable `JsonValue` wire mappers for the three shipped providers,
including the Claude streaming state machine `ToolUp.AI.Wire.ClaudeStreaming` (Phases 252–254); and
the Fable-host portability conformance pack (Phase 255). The provider companions'
(`ToolUp.AIProviders.{Claude,OpenAI,Gemini}`) public surfaces are **unchanged** — the transport
migration is internal.

**Source-compatible; assembly identity changed.** `open ToolUp.Platform.AI` and all the type names
above compile unchanged — the relocation is namespace-preserving. What breaks is a **mixed-version
package graph**: `ToolUp.Platform.Core` 0.10.0 floors on `ToolUp.AI.Wire` 0.10.0, so pinning it
next to any `ToolUp.AI.*` 0.9.x (or the reverse) fails at **restore** with `NU1605` / `NU1109`
version-conflict errors — before the compiler ever runs. The whole `ToolUp.*` pin set must move to
0.10.0 together.

## Migration

`Directory.Packages.props` — via the `ToolUp.Sdk` meta-manifest:

```diff
-    <ToolUpSdkVersion>0.9.4</ToolUpSdkVersion>
+    <ToolUpSdkVersion>0.10.0</ToolUpSdkVersion>
```

or, with per-package pins, bump **every** `ToolUp.*` pin in one commit:

```diff
-    <PackageVersion Include="ToolUp.Platform.Core" Version="0.9.4" />
-    <PackageVersion Include="ToolUp.AI.Core" Version="0.9.4" />
-    <PackageVersion Include="ToolUp.AI.Wire" Version="0.9.4" />
+    <PackageVersion Include="ToolUp.Platform.Core" Version="0.10.0" />
+    <PackageVersion Include="ToolUp.AI.Core" Version="0.10.0" />
+    <PackageVersion Include="ToolUp.AI.Wire" Version="0.10.0" />
```

Source files — **no change** for consumers of the connector types or implementers of
`IAIProvider`. Two rare exceptions:

- Reflection / serialization over an **assembly-qualified** name of a connector type: update the
  assembly component from `ToolUp.Platform.Core` to `ToolUp.AI.Wire`.
- A Fable client that consumed the connector types via `ToolUp.Platform.Core`'s `fable/` sources:
  the types now extract from the `ToolUp.AI.Wire` package (also packed `fable/`), which arrives
  transitively; add an explicit `ToolUp.AI.Wire` reference only if your tooling doesn't surface
  transitive Fable sources.

Optionally, custom `IAIProvider` implementations can now delete hand-rolled retry / error-mapping
code in favour of `RetryRunner.run`, `ErrorClassifier`, and `IHttpTransport` (inject a fake
transport in tests — no HTTP stubbing).

## Verification

1. `dotnet build` clean on the consumer sln, with **zero NuGet downgrade / version-conflict
   warnings** — a mixed pin set fails at restore (`NU1605` / `NU1109`), loudly.
2. Fable clients: `dotnet fable -o output --noCache` clean from the client project.
3. If the deployment composes AI: run one assistant round-trip (message + tool call) against a
   configured provider.

## Rollback

Repin to 0.9.4 (revert the `Directory.Packages.props` diff) — there are no source edits to revert.
