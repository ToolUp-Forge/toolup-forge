# 0.24.0 — the transport seam moves to `ToolUp.Platform.Transport`

**Phase 128. Breaking, on the 0.24.0 draft: source-compatible after one `open`, binary-breaking.**
Types change namespace and assembly; consumers recompile.

## What moved

A new package, **`ToolUp.Platform.Transport`**, is the lowest tier of the SDK (FSharp.Core only,
Fable-compiled, source shipped under `fable/` like `ToolUp.AI.Wire`). Everything below now lives
there, in namespace **`ToolUp.Platform.Transport`**:

| Symbol | Was (package · namespace) | Now (package · namespace) |
|---|---|---|
| `RetryPolicy` (+ module: `defaults`, `noRetry`, `delayFor`, `clampTimeoutMs`, `timeoutDescription`) | `ToolUp.AI.Wire` · `ToolUp.Platform` | `ToolUp.Platform.Transport` · `ToolUp.Platform.Transport` |
| `HttpRequest` (+ `HttpRequest.post`), `HttpResponse` (+ `HttpResponse.isSuccess`), `IHttpTransport` | `ToolUp.AI.Wire` · `ToolUp.Platform.AI` | `ToolUp.Platform.Transport` · `ToolUp.Platform.Transport` |
| `HttpClientTransport` (the BCL `HttpClient` adapter) | `ToolUp.AI.Server` · `ToolUp.Platform.AI` | `ToolUp.Platform.Server` · `ToolUp.Platform.Transport` |

New beside them: `TransportError`, `TransportClassifier`, `RetryClass`, `TransportRetry`, `HttpCall`.
`ToolUp.AI.Wire` keeps only AI semantics — `AIProviderError`, `ErrorClassifier` (now a projection of
`TransportClassifier`) and `RetryRunner` (now a wrapper over `TransportRetry.runWith`) — with
unchanged behaviour. The package arrives transitively through `ToolUp.Platform.Core` and
`ToolUp.AI.Wire`; a consumer importing `ToolUp.Sdk.props` gets its `PackageVersion` from there.

The outbound API connector kit in `ToolUp.DataSources.Common` is new in this release, so it has
no consumers to migrate. For the record, its retry policy is declared per connector
(`IExternalApiConnector.BackPressure.Retry`), and `PagedFetchOptions.Retry` is an optional per-run
override (`RetryPolicy option`, `None` by default) that only `ExternalApi.effectiveRetry` reads.
The same release adds `RetryPolicy.validate`.

## The change, per consumer file shape

A file that names `RetryPolicy` and opened only `ToolUp.Platform`:

```diff
+open ToolUp.Platform.Transport
 open ToolUp.Platform
```

A file that uses the HTTP seam (an AI provider, a host transport, a test fake):

```diff
+open ToolUp.Platform.Transport
 open ToolUp.Platform.AI   // still needed for AIProviderError, ErrorClassifier, RetryRunner, …
```

A fully qualified reference:

```diff
-let policy: ToolUp.Platform.RetryPolicy = ToolUp.Platform.RetryPolicy.defaults
+let policy: ToolUp.Platform.Transport.RetryPolicy = ToolUp.Platform.Transport.RetryPolicy.defaults
```

A project that referenced `ToolUp.AI.Server` only for `HttpClientTransport` can reference
`ToolUp.Platform.Server` instead; every `ToolUp.AI.Server` consumer already has it transitively.

**Placement of the new `open`:** put it *before* `open Microsoft.AspNetCore.Http` (or Giraffe) in a
file that opens both — ASP.NET Core has its own `HttpRequest` / `HttpResponse`, and the later `open`
wins.

## Verify

1. `dotnet build` — a missed file fails with `FS0039: The type 'RetryPolicy' is not defined` (or
   `'IHttpTransport'`, `'HttpRequest'`); add the `open` it names.
2. Search for stale qualified names: `ToolUp.Platform.RetryPolicy`, `ToolUp.Platform.AI.HttpRequest`,
   `ToolUp.Platform.AI.HttpResponse`, `ToolUp.Platform.AI.IHttpTransport`,
   `ToolUp.Platform.AI.HttpClientTransport` — none should remain.
3. Run your test suite: behaviour is unchanged (the AI retry and classification rules are pinned
   by the SDK's own tests over the shared loop).

## Rollback

Pin the `ToolUp.*` packages back to `0.23.0` and drop the added `open` lines; nothing persisted
changes shape, so no data migration is involved.
