# 0.6.1 — `StateViews.inlineLoading` renders the ToolUp brand mark

**Shipped:** SDK 0.6.1 (`feat(client)` `0245e8c`).
**Class:** visual-only, non-breaking. **Consumer action: none.**

## What changed

`Toolup.UIToolkit.StateViews.inlineLoading` — the inline "recomputing while
showing stale results" indicator used by module page views — previously drew a
neutral gray spinner ring:

```fsharp
Html.div [ prop.className "w-4 h-4 border-2 border-gray-300 border-t-brand rounded-full animate-spin" ]
```

It now renders the ToolUp brand mark (`ToolUp.Platform.Icons.dataLoading`, the
colour-cycling chevron-and-dot, self-animated via SMIL), so an inline loading
state matches the `BrandMarkLoader` boot indicator instead of a bare circle.
The flex row + label are unchanged; only the spinning circle became the brand
mark.

This is the one `StateViews` helper that is intentionally brand-specific — the
others (`emptyState` / `noData` / `errorBanner`) still take a caller-supplied
icon.

## Consumer action

None. The change is internal to the SDK helper; every call site picks it up on
the version bump. Adopt by bumping `<ToolUpSdkVersion>` to `0.6.1` (or higher)
whenever convenient — there is no code change and no behavioural change beyond
the rendered glyph.

Apps that deliberately prefer a neutral spinner over the brand mark have no
opt-out on this helper today; raise a forge TIDY-UP if a config-driven
(`LoadingIndicator`-aware) variant is wanted.

## Verification

After bumping the pin, any page with a "recomputing" state (e.g. the media-spend
analysis pages — Spend Trends / Sankey / Performance Breakdown / Efficiency)
shows the colour-cycling brand mark instead of a gray ring while it recomputes.

## Rollback

Pin back to `0.6.0`. No data, schema, or API surface is involved.
