# 0.7.0 — release roll-up

**Shipped:** SDK 0.7.0 (supersedes [0.6.1](0.6.1-inline-loading-brand-mark.md)).
**Class:** additive minor. **Consumer action: none required** — every change in
this release is additive, opt-in, and default-off (GP 11 / GP 13), so an existing
deployment that bumps its pin stays byte-for-byte identical until it opts in.

The minor bump (rather than a patch) reflects the breadth of new public surface
landed since 0.6.1 — several new substrate interfaces, a new optional analyzer
package, and a client theming contract — not any breaking change. There are no
removed or changed signatures in this release.

## What's in this release

Each change carries its own scoped migration doc; this roll-up links them and
records the consumer-action class. Adopt any individual change independently —
they are not coupled.

### Hardening (behaviour change, no consumer action)

- `fix(remoting)` — the auth deny reason is now redacted from the wire message
  text returned to the client (the full reason still reaches the audit trail).
  No API surface change; failed-authorisation responses simply carry less
  internal detail. No consumer code change.

### Internal quality (no public surface)

Several test-only / fitness-gate phases landed in this window and require no
adoption: Phase 174 (architecture-fitness dependency-direction gate), Phase 175
(public-API approval baseline / SemVer guard), Phase 196 (adversarial
fail-closed test pack), and Phase 224 (client-toolkit theming-contract tests).

## Consumer action

None. Bump `<ToolUpSdkVersion>` to `0.7.0` (or the relevant per-package
`<PackageVersion>`) in your `Directory.Packages.props` whenever convenient, then
adopt any of the opt-in features above on your own schedule by following its
scoped migration doc. Nothing in this release changes prior behaviour until you
opt in.

## Verification

After bumping the pin: `dotnet build` (no new warnings or errors from the version
change alone), then a smoke-test boot of the shell. None of the changes above
alter the default-composition render or wire shape, so an un-opted deployment
behaves identically to 0.6.1.

## Rollback

Pin back to `0.6.1`. No data, schema, or API surface is involved in the version
bump itself; opt-in features that were never composed leave nothing to roll back.
